# SportX movement practice prototype

SportX is a browser-based movement practice prototype with static pose correction, continuous rowing feedback and video review.

Local network preview: run `npm run dev`, then open the printed LAN address on a phone connected to the same LAN. Use the computer's current IPv4 address, which can change with DHCP. The preview listens on all interfaces by default; use `npm run dev -- --host 127.0.0.1` for a loopback-only preview. Allow TCP port 5187 on private networks if Windows Firewall blocks other devices. HTTP LAN access supports the movement library and 3D playback; phone camera access requires a trusted HTTPS connection. Phone layouts support horizontal movement selection, touch-sized controls and portrait/landscape viewing.


A browser-only prototype using Three.js 0.180.0 and MediaPipe Tasks Vision 0.10.21.

Edit the application in `src/`. Run `npm run dev` to serve it at `http://127.0.0.1:5187/`, or serve `src/` using any static HTTP server. Keep that terminal open while using the preview. Run `npm test` for the pose checks. `npm run build` copies public application files into the ignored `build/` folder used for hosting; no dependencies need to be installed. Camera access is opt-in; frames are processed locally and never uploaded. Libraries, fonts and the pose model load from third-party CDNs, so the first visit requires network access.

The training figure uses contoured surfaces in `src/athlete-model.mjs`: shaped torso and pelvis, tapered limbs and sleeves, facial features, and layered trainers. Surfaces follow the existing joint positions, with separate head and hip rotations and the existing equipment hand frames. Tennis uses a white cap, navy polo, white shorts, wristband and socks, with a black/white racket with an open throat and individual strings. Rowing has a red sleeveless singlet, dark shorts with pale side panels, bare limbs and sports glasses, following its measured skeleton. Shooting has its own fitted black long sleeves, slim trousers, cap and black trainers, with a smaller black exterior prop based on the supplied photographs; tracking markers are omitted. ## Rowing static correction

Static checkpoints now advance automatically after every required joint is observable and all measured limbs remain aligned together for one second. Passing the last checkpoint enters dynamic practice for that movement. To skip static practice, choose **Dynamic recording** next to **Start correction** once the camera direction is ready, then start the countdown. Speech playback has its own switch and does not require microphone or voice-control opt-in.

Dynamic practice supports button or voice start/finish, a three-second countdown, a faint animated expert overlay with independent visibility/opacity, and expert start-time/speed controls before recording. The camera video and timestamped pose samples stay in the browser; no microphone audio is included in the recorded video. Record about three strokes, then finish. Voice finish uses speech onset as its cutoff; automatic trimming retains confirmed complete cycles. Inspect and adjust the trim when no complete cycle can be confirmed.

Recording now matches the current action phase live and shows only persistent orange error segments with animated dashed curved arrows. Corrected segments flash green briefly, then disappear; already-correct visible skeletons remain hidden. During recording, the expert guide follows an independent clock at the selected speed and keeps its initial scale/anchor so student tracking jitter cannot change its rhythm. Feedback still compares against the matched student phase; replay uses the final matched reference. The live guide caps 3D rendering at 20 FPS (12 FPS when expensive) and 720 pixels wide, reusing the last frame between updates. Export uses full resolution. Recording prefers VP8 over VP9 to reduce encoding pressure, and export has only one compositing loop. Final analysis runs in a local Web Worker. Constrained monotonic cyclic DTW matches the captured expert sequence to the user's tempo; missing observations cannot advance the sequence. Observable joint deviations must persist for at least 0.3 seconds to appear as corrections. Early arm bending during leg drive has a separate sequence cue. Replay includes synchronized expert overlay, error-only pose highlights, dashed direction arrows, issue jump links, slow playback and looping. The result shows separate visible-part scores and an equal-part mean total, each out of 100, with observable coverage. Scores use time-weighted angular similarity (100 × max(0, 1 − (angle error / tolerance)² / 9)); each part needs at least 0.5 seconds of observations. Hidden joints and gaps are unscored and reduce coverage; the total reflects observed parts and does not grade unseen form or movement timing. Trimming recalculates the scores. Export renders the selected video range with these annotations and optional debug FPS into a downloadable MP4 (H.264 preferred); browsers without MP4 encoding show an explicit WebM fallback. Settlement and export always use a separate fully opaque expert column. A progress bar tracks rendered video time, stays below 100% during finalization, and reaches 100% when the download is ready. Keep the page visible during export. Occluded joints remain unknown; camera angle and partial tracking can limit cycle detection and feedback.

Run `npm run test:dynamic` for alignment and completion checks. `npm run test:dynamic:browser` uses installed Chrome with a simulated camera and pose detector to exercise automatic progression, voice recording, trimming, annotated export and mobile layout. Real-camera acceptance is still required for tracking quality.

Enable the camera on the main Rowing practice page to estimate horizontal direction from visible shoulders and, when available, hips. The expert model follows a continuous angle. Once direction is stable, **Start correction** locks that angle and opens the enlarged camera view with a translucent clothed expert model. **Reposition** returns to the main page for a new direction estimate. Each stage has a short status and next action. The shared **Mirror** toggle flips the camera, expert and live joints together without changing anatomical labels, the locked direction or angle feedback.

Switching checkpoints starts a 3-second expert demonstration: expert opacity is 0.95 and the camera is dimmed, so the target is prominent. Normal camera brightness and the selected overlay opacity then return with a plain-language adjustment cue. Errors persisting for 1.2 seconds get only their affected live segments plus animated curved movement arrows; nine seconds of visible misalignment repeat the expert demonstration. Missing tracking does not count as failure. Visible shoulder/elbow pairs can produce upper-arm-height cues even when a wrist is cropped or the elbow bend is end-on. The status names individual missing joints and distinguishes out-of-frame joints. Height-only agreement does not claim a fully correct arm. Arrows share the raw-coordinate projection and mirror transform with the camera and model; reduced-motion settings show a static arrow. A previously incorrect limb must remain aligned for 600 ms before a green confirmation and brief green overlay appear for 1.4 seconds, then disappear. Overall visible alignment requires 800 ms of stability and shows a concise green confirmation; partial visibility is labeled explicitly. Angle details are collapsed.

Arms-only has two static checkpoints, half stroke has three and full stroke has four. Visible joint triplets can be compared without full-body acquisition; arms-only does not require hips or legs. The current half-stroke capture predominantly uses arms and torso rather than a half slide. Reference joints and the model share the same horizontal projection. End-on segments are omitted, and a direction change pauses feedback instead of rotating the locked model to hide it. Camera pitch and precise camera calibration are not estimated; monocular depth and perspective remain limitations.

`npm test` includes continuous-angle, lock/reposition, partial-joint and camera lifecycle checks. With the local server running on port 5187, `node scripts/rowing-browser-check.mjs` uses Chrome, a canvas video stream and mocked inference to check the outside-to-correction flow, actual expert mesh rendering, mirror synchronization, model gender, localization and desktop/mobile bounds. These checks do not validate real webcam inference.

## Prerecorded rowing speech

### Browser voice control

**Enable voice control** opts into the browser's `SpeechRecognition` / `webkitSpeechRecognition` service. It needs no application backend, account, API token or server-side secret and works from the HTTPS GitHub Pages site. Recognition support, Chinese/English availability and service connectivity vary by device; the browser may process microphone audio through an online service. Unsupported browsers retain touch controls. Native recognition has not been verified with a real microphone on the target phones.

The **Speech** selector independently sets English or Mandarin recognition and remembers that choice; changing the interface language does not reset it. Commands include: start/end/pause/resume correction; show/repeat demonstration; repeat instruction; next/previous stage (wraps); next/previous rowing movement; lock direction; reposition; camera on/off, next lens, front/back flip; mirror on/off; voice control off. Known aliases and bounded spelling-distance matching repair short transcription errors such as “art correction” → “start correction”. Ambiguous matches, negated sentences and guessed on/off polarity are rejected. Final results execute commands; distinct interim commands may silence playback without executing an action. The heard text and interpreted command are displayed together. Starting correction also locks the prepared direction. Turning the camera off retains voice control so the camera can be reopened by voice.

Recognition continues during prerecorded cues and browser-synthesized command acknowledgments. Known current/recent playback text filters echo, including fuzzy transcripts of quoted commands. A distinct command interrupts playback; “Coach, …” / “教练，…” distinguishes a user interruption when the desired command is also quoted in the audio. This text filter does not perform acoustic speaker separation. Changing the speech language restarts recognition; hidden pages suspend it. Permission, language and network errors stop automatic retries and offer a user-triggered retry.

**Pause correction** and **View demonstration** preserve the checkpoint and locked direction. Tracking, error timers, arrows and missing-joint/reposition speech pause while the user walks back to see the model. **Resume correction** waits for visible joints before resuming direction checks. Viewing the model does not return to direction preparation. These controls are also available as buttons inside correction.

`node tests/voice-control.mjs` verifies parsing, negation rejection, duplicate final results, fuzzy matching, echo filtering, playback interruption, independent speech-language selection and error handling. The browser regression uses mocked recognition results and a simulated camera to verify command wiring, stage wrapping, video stop/start and preservation of review state; it does not validate microphone transcription quality.

Automated browser checks always launch Chrome with `--mute-audio`. Playback and decoding can be checked silently; audible voice previews are reserved for an explicitly requested listening review.

The bilingual cue inventory has 57 semantic entries: 6 flow prompts, 8 checkpoint prompts, 20 adjustments, 9 confirmations and 14 tracking/framing messages. Each has a separate English and Mandarin MP3 under `src/assets/audio/rowing/en/` and `src/assets/audio/rowing/zh/`. `manifest.json` maps text, voice, duration, size and SHA-256 to all 114 clips. `sample-en.mp3` and `sample-zh.mp3` combine eight representative cues for review. The complete bilingual list is in [docs/ROWING-VOICE-LINES.md](docs/ROWING-VOICE-LINES.md).

Audio uses offline Windows Speech Synthesis with Microsoft Zira (en-US) and Microsoft Huihui (zh-CN), rate 0.95, then ffmpeg normalization and encoding to 24 kHz mono 64 kbps MP3. `node scripts/generate-rowing-speech.mjs` regenerates the assets on Windows with these voices and ffmpeg/ffprobe installed; intermediate WAV files stay in ignored `.local/`. `node tests/rowing-speech.mjs` verifies inventory, audio metadata and content hashes.

Rowing preparation and correction play these clips in the selected UI language. Voice controls appear outside and inside correction. The **Speech · On/Off** playback button is independent of microphone permission and voice control. Disabling recognition or a recognition-service error leaves speech playback available. Checkpoint demonstrations, persistent limb adjustments, tracking guidance and successful corrections have matching cues. Playback replaces stale instructions, debounces tracking loss and rate-limits repetition. A valid adjustment takes priority over an ordinary missing-joint notice. Closing correction, switching language or hiding the page cancels current speech. If browser autoplay blocks sound, tap the voice button to enable it. `node tests/rowing-speech-playback.mjs` checks scheduling and interruption; `node scripts/rowing-browser-check.mjs` checks actual English/Chinese MP3 playback, mute and visual correction together.

Elbow-height guidance calibrates against visible shoulders/torso rather than the moving arm. Without a stable body anchor it does not invent an elevation target. When only height can be measured, stable height alignment shows a specific height confirmation and asks the user to hold it; an end-on elbow angle is described as unmeasurable from that view, separately from genuinely missing elbow landmarks. Height-only feedback never claims full pose alignment.

## Limitations

This is not clinically validated. Rules check a few 2D landmark relationships, not pain, joint loading, balance, depth, or injury risk. Thresholds are illustrative product heuristics and must be reviewed by qualified movement professionals before safety-related use. Poor framing, camera angle, occlusion and clothing can produce inaccurate feedback. Never interpret a matching reference as a guarantee of safe form. Lifting and additional exercises are not yet included.

## Pose continuity and performance

The camera view shows live camera FPS, pose-inference FPS, average inference latency, and overlay FPS. At actual recording start, counters reset and performance samples are retained with their time ranges. Finish keeps the full series. Replay, seeking and export show the recorded sample for that original timestamp, including actual expert mesh FPS, rather than replay/export speed or a single recording average. A new recording starts fresh. These are separate measurements; a smooth camera feed does not imply equally frequent pose estimates. Live phase matching caches expert angular features and computes only one full pose assessment per observation. Repeated expert mesh renders are reused.

Short arm occlusions retain a marked blue dashed estimate for up to 450 ms using recent user geometry, torso motion, and two-bone elbow reconstruction. A consistent current 3D body projection can also supply an explicitly inferred point. Inferred joints do not trigger corrective arrows or pass static checkpoints. Recent supported estimates contribute reduced-weight pose scores and phase continuity; they cannot independently confirm a cycle. Foreshortened visible limbs use valid 3D joint angles when screen-space angles are ambiguous; depth-only corrections do not produce a misleading up/down arrow. These are geometric and temporal estimates, not a new trained pose model, and cannot uniquely recover every hidden pose from a single camera.

## Background pose inference

### Take recording and settlement

Settlement has a collapsed **Debug tools** section for **Show complete skeleton**, **Show FPS (also in download)** and **Export as data**. FPS is hidden by default in normal use; its checkbox controls settlement/live display and the annotated download, while recorded measurements remain available in JSON. **Download original video** is a normal download action and preserves the entire untouched camera recording in its native format, without trimming or graphics. The JSON pairs with it by session ID/source filename and retains actual inference timestamps, raw/tracked/inferred points, evidence weights, live/final phase decisions, per-frame metrics and all take scores. No artificial per-video-frame pose predictions are inserted.

Static correction and dynamic live practice offer **Overlay / Side by side**. Overlay retains adjustable opacity; the side-by-side expert is fully opaque and the user's camera stays undimmed. Dynamic settlement/export always use two columns. During 3–2–1, both modes hold the selected starting pose (default: first learning checkpoint); overlay holds an absolute 90% opacity from 3 through 1.5 seconds remaining, then drops to the selected live opacity over 250 ms, while side-by-side stays fully opaque. The countdown expert remains visible even if the live overlay is switched off. The expert starts moving only when recording begins. The existing pose is kept through countdown setup to avoid a transient fallback placement.

`Camera` FPS measures presented video frames, not the camera sensor or encoded file cadence. Those can differ under load. Browser test downloads are isolated in `artifacts/browser-downloads`, never the user's default Downloads directory.

Recent reconstructed points now contribute confidence-weighted pose scores and motion-phase continuity. Two-bone IK requires measured shoulder/wrist anchors; temporal estimates decay and all estimates expire at 450 ms for scoring. Weights are heuristic, capped at 0.75, and low-confidence points are excluded. Both within-limb and between-limb aggregation use evidence weights. Estimated-only evidence cannot establish a completed phase/cycle boundary. `inferredShare` records each score's estimated evidence fraction; blue `≈` deductions identify estimated metrics. Unobservable depth angles remain unscored. Static checkpoint confirmation still requires measured joints. Unit coverage: `node tests/rowing-debug.mjs`.

Settlement and downloaded clips show two columns: the user's video and corrections on the left, a fully opaque synchronized expert on the right. Expert opacity/visibility controls apply only before/during live practice. Take selection occupies a full row, separate from playback controls. Finishing recording stops source and cloned camera tracks; restart and dynamic reposition can reacquire the selected camera. Closing static/dynamic correction stops all camera tracks, while explicit static Reposition returns to preparation with the camera retained.

Settlement phase alignment uses robust normalized visible movement trajectories (wrist/elbow movement relative to the shoulder, and shoulder movement relative to the hip where available), with direction changes as evidence. Pose-angle error is scored after phase matching instead of being the primary phase cost. Initial phase offset, initial reaction holds and uniform speed changes are handled automatically; interior pauses can affect rhythm without reducing pose accuracy or cycle completeness. Timing uses reliably distinguishable phase anchors and the active motion interval. If there are too few reliable anchors, timing/completion/total are withheld as unconfirmed, while measured limb scores remain visible. `node tests/rowing-motion-phase.mjs` covers these cases, including a cropped partial take and frontal visible-arm input. No new model is run during this alignment.

Video export decodes and seeks each source frame, renders the same settlement overlay at that source timestamp, and encodes fixed 25 FPS timestamps through WebCodecs. H.264 frames are muxed into MP4; VP8/WebM is the fallback. Export does not use realtime playback or MediaRecorder, so decode/render/encode delays cannot become frozen seconds in the output. The expert and animated arrows use media time in settlement/export, and export snapshots gender and mirror settings; live visibility/opacity do not affect the separate expert column. A current browser with WebCodecs is required. Run `node scripts/rowing-frame-export-browser-check.mjs` to test both formats with deliberate rendering delays and inspect decoded colors, durations and frame timestamps.

Dynamic practice displays Take numbers and uses the existing causal phase matcher at cycle boundaries. The guide may wait at most 2.5 seconds for a still-active previous repetition; no additional model or language-model call is used. Settlement segments matched cycles, scores each take, and initially selects the highest score. Take controls show original start/end timestamps; the global scrubber shows current recording time, take number and time within the selected take. Estimated checkpoint markers correspond to the existing static learning poses.

Replay interpolates expert timestamps along the monotonic match, allowing moderate tempo stretching. Pose and timing scores are separate: total is `(80% pose + 20% timing) × observed cycle completeness`, with a penalty for ranges containing substantially more than one cycle. Uniform tempo changes up to 2x are tolerated; nonlinear timing residuals and excessive stretch reduce timing credit. Missing parts remain unscored. Local labels show each measured angle's loss from 100, rather than penalties that can be directly summed into the take total. Numeric deductions appear only in replay/export, never live practice.

Custom start/end ranges are sent back through worker alignment and scored again as a custom take; calling a partial range a full take does not bypass completeness checks. Export downloads only the selected take, including its annotations and optional debug FPS, followed by a 2.5-second scorecard. Reposition preserves the current settlement, calibrates the next recording's direction, and leaves the old take's reference view unchanged. Start again begins a fresh recording with countdown.

Preparation yields to the UI and can be cancelled on close; actual recording retains live pose inference.

Dynamic scoring now marks model-depth angles as view-limited when limb foreshortening or strong image/world-angle disagreement makes the angle unreliable. These angles do not generate certain corrections or deductions; image-space height hints remain separate. Per-part limitations lasting at least 0.5 seconds produce short camera/framing suggestions. Inferred raw geometry, depth flags and candidate scores remain in JSON, with excluded metrics carrying zero scoring weight. This is a conservative visibility gate, not a replacement pose model or calibrated depth estimate. `tests/rowing-view-feedback.mjs` and the end-on fixture in `tests/rowing-correction.mjs` cover these rules.

Review playback controls include a regular, default-off “Show arrows during playback” checkbox. Paused review always shows supported direction arrows; enabling the checkbox keeps them visible during playback. Take shortcut buttons contain only their number, the selector contains number/score, and timing remains in the timeline, trim controls and shortcut tooltips.
